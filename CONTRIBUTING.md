# Contributing to ProductForge

Thanks for helping! Issues and pull requests are welcome — bug reports from real runs are the most
valuable kind (the fixes in [`docs/dogfood-v1.1.md`](docs/dogfood-v1.1.md) and
[`docs/dogfood-v2.md`](docs/dogfood-v2.md) all started that way).

## Before you start

1. Read [`CLAUDE.md`](CLAUDE.md). Its golden rules are not optional: stages are enforced, evidence
   stays separate from inference, scripts do the arithmetic, agents write only to staging, the
   runtime is standard-library only, and the guardrails are absolute.
2. Set up the dev tools and run the suite — see [`DEVELOPMENT.md`](DEVELOPMENT.md).
   `make check` must be green before and after your change.

## How to change things

Follow the **extension recipes** in [`CLAUDE.md`](CLAUDE.md#extension-recipes) — new artifact,
new finding code, new config knob, new gate condition, new delegated capability, new command.
Each names every place that must change together.

- **Fixtures** are generated by `tests/fixtures/build_tasklet.py`; edit the generator, never the
  snapshots (`make fixtures-check` catches drift). `examples/tasklet/` is generated the same way.
- **Every finding code** has one `tests/fixtures/invalid/<CODE>.md` overlay that yields exactly
  that code, and a row in `skills/productforge/references/record-format.md`.
- **Config knobs** live in `pflib/config.py` and `docs/configuration.md` (a test keeps them equal).
- **Prompts** (SKILL.md, references, agents) have contract tests; keep SKILL.md under 400 lines —
  stage procedures belong in `references/commands-*.md`.
- **Never** put real third-party content in fixtures, examples or docs — synthetic `.example`
  products only; dogfood reports carry aggregates and paraphrase.

## Reporting a bug from a run

Include the command, the `pf.py status --json` counts, the failing `pf.py check` condition or
validator code, and — if you can — the staged file that misbehaved (redact the product's content).
Security issues: see [`SECURITY.md`](SECURITY.md).
